평소 [섞인 커밋 분리 워크플로우]·[클린 커밋 히스토리 관리] 원칙을 유지하되, 두 조건이 모두 충족되면 분리 스킵을 허용합니다.

1. 섞인 변경들이 **같은 페이지 또는 같은 도메인**으로 응집되어 있다 (커밋 메시지가 둘을 자연스럽게 포괄 가능)
2. **MVP/릴리스 마감이 임박**해 reset/rebase의 회귀 위험이 분리 이득보다 크다

**Why**: 2026-05-12 sticky offset 정리(`top-14`→`top-0`)가 이미 다른 세션 작업(UserPen→ProfileEditIcon)과 같은 ProfilePage 커밋 `9d20b2b`에 묶여 있었음. 두 변경 모두 ProfilePage 도메인이라 응집되어 있었고 MVP 발표 D-3 상황이라 reset+재커밋 위험이 가치보다 높았습니다. 사용자 판단: "두 작업 모두 프로필 페이지에 관한 내용이라 괜찮을 것 같다" → 분리 스킵 합의.

**How to apply**:
- 섞인 커밋 발견 시 두 조건(응집성 + 마감 임박) 체크
- 둘 다 yes면 분리 스킵 + 다음 push 때 커밋 메시지에 누락된 변경이 있다는 점만 인지하고 진행
- 둘 중 하나라도 no면 기존 워크플로우(reset --mixed + stash -u)로 분리
- 평소 작업에서는 여전히 분리가 default — 이건 명시적 예외 허용 조건
