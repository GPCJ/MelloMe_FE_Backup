리텐션 개선 방향 분석 (2026-06-11 주간회의 준비 중 도출). GA4상 이탈률은 양호하나 리텐션이 약함 = **유입된 사용자가 다시 안 돌아옴**.

## 갭의 정체 — 도달(reach) 채널 부재
알림이 **앱 접속 중(SSE 연결)에만 도달**한다. 탭 닫으면 연결이 끊겨(`useNotificationSSE.ts:78` abort) 실시간 토스트도 안 뜸. 알림 자체는 서버에 보존되고 탭 복귀 시 동기화되지만(`:64` visibilitychange), **떠나 있는 사용자를 능동적으로 부르는 채널이 0**이다. 이게 리텐션 갭의 핵심.

## 채널 × 돌아올 이유 — 둘 다 필요
도달 채널은 전달 수단일 뿐, **돌아올 이유(콘텐츠/가치)가 없으면 무의미**. 두 축을 같이 봐야 함.

### 도달 채널
- **이메일**: 한국 사용자 열람률 낮아 약함 (사용자 직감 = 효과 의문, 동의)
- **카카오 알림톡** ⭐: 한국 도달률 최강. 단 **정보성 메시지만 가능**(고민카드 답변/새 팔로워/안 읽은 쪽지). 광고·홍보성(새 활동지 알림 등)은 **친구톡**(채널 친구 추가자 한정) 영역 — 혼동 시 템플릿 심사 반려.
- **Web Push**: 웹앱에 자연스럽고 즉시성 좋음. **PWA 게이트** — iOS는 16.4+ "홈 화면 추가" 설치 시에만 동작. FE가 직접 주도 가능한 영역(vite-plugin-pwa). ⚠️ 기존 vite-prerender-plugin(SEO)과 Service Worker 상호작용 검증 필요.

### 돌아올 이유
- **정기 활동지 리듬** ⭐: 활동지 1건이 모든 소셜 기능보다 큰 유입을 냈으므로(06.09 spike), "매주 화요일=활동지"식 예측 가능 리듬으로 습관화. 검증된 유입 hook을 리텐션 장치로 재활용.
- 고민카드 답변 알림(개인 투자), 온보딩 첫 주 정착(06.09 가입 9 중 인증완료 2 = 초기 이탈 큼).

## 카카오 알림톡 선행조건 (대부분 FE 밖, 회의 안건)
순서대로 막히는 게이트:
1. 🚧 **사업자 등록** — 알림톡은 사업자 전용. 돌고래브릿지(갭이어) 등록 여부 확인 필요
2. 🚧 **사용자 휴대폰 번호 수집** — 알림톡은 번호로 발송. 현재 가입이 이메일/구글이면 번호 부재 → 가입 폼에 번호+수신동의 추가 (**유일한 FE 작업**)
3. 카카오톡 채널 개설 + 발신프로필 심사
4. 메시지 대행사(솔라피/알리고/NHN 등) API 연동 (BE)
5. 템플릿 사전 심사(자유 텍스트 불가)
6. 건당 과금(대략 8~15원/건)

→ FE는 번호 수집 폼 정도. 나머지는 사업자·BE·PM 결정이라 **본인 주도 X, 회의에서 "사업자 등록됐나? 번호 수집할까?" 던질 안건**.
