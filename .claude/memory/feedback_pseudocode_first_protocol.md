코드 도움 요청이 오면 코드 대신 먼저 아래 프로토콜을 적용합니다.

**Why:**
사용자가 스스로 생각하지 않고 완성된 코드를 요청하는 패턴이 반복됨. 키워드 감지는 어휘 우회로 효과 없음. pseudocode 선행 + 막막함 분기 대응으로 대체.

**How to apply:**

## 코드 요청 전 — pseudocode 의무화

"이 함수(기능)가 해야 할 일을 한국어로 3단계로 말해봐"를 먼저 물어봄.
설명 못하면 아직 생각 안 한 것 → 생각 먼저 하도록 유도.

## 막막하다고 하면 — 코드 절대 먼저 안 줌

A. **피로/귀찮음에서 오는 막막함** ("하기 싫다", "오늘은 도저히")
→ "잠깐 쉬고 와" 권유. 억지로 붙잡아봤자 흡수 안 됨.

B. **몰라서 오는 막막함** ("어디서 시작해야 할지 모르겠다")
→ 아래 순서로만 도움:
1. "어느 부분이 막막해?" (범위 좁히기)
2. 개념 이름 힌트만 (코드 X)
3. 같이 pseudocode 단위로 쪼개기
4. 그래도 막히면 → 그 다음 단계만 질문

코드를 주는 것은 언제나 마지막 수단이며, 막막하다는 말 자체가 코드 생성 트리거가 되어서는 안 됨.

## 보완 — 사용자는 의사코드 작성 경험이 없음 (2026-06-05)

"의사코드 적어본 적 없어서 어떻게 적는지 모른다"고 직접 밝힘. 의사코드를 요구만 하면 포맷을 몰라 막힘 → 그냥 코드로 직행하려 함. 진입을 도와야 한다:
- "의사코드는 **특별한 문법이 아니라 한국어로 순서를 적는 것**"이라고 먼저 탈신비화.
- **사용자가 직전에 말로 한 설명이 곧 의사코드**임을 짚어줌(이번 세션에서 답장 기능 동작을 줄글로 다 설명했는데 그게 의사코드였음을 보여주자 진입함).
- 그 줄글을 [선언/화면/동작/성공 후] 같은 짧은 순서 목록으로 정리해 보여주고, 그걸 코드로 옮기게 함.
