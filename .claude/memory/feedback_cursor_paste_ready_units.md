사용자는 Cursor IDE를 쓴다. 새 로직 구현(본인작성 트랙, [[feedback_direct_coding_default]])을 가이드할 때, 코드를 대신 쓰지 말고 **작은 단위로 쪼갠 "복붙 가능한 순수 지시문"**을 텍스트로 준다.

워크플로우: 내가 단위별 지시문 텍스트 제공 → 사용자가 Cursor에 지시 → IDE에서 diff 확인·이해 → 다음 단위. 사용자가 코드를 직접 touch하고 매 diff를 이해하므로 하이브리드 본인작성 정신이 유지된다.

형식 규칙:
- blockquote(`>`) 마크업 금지 — 그냥 코드블록(```)에 평문 지시 담기.
- "이 단위에서 봐야 할 것" 같은 메타/체크 섹션 금지. 지시문 = Cursor에 바로 붙여넣을 내용만.
- 단위는 작게 (예: ①파일 골격+핵심 분기 / ②트리거 / ③핸들러).

**Why:** 첫 시도에서 blockquote + "체크할 것" 메타 섹션을 줬더니 "이거 빼고 다시 뽑아줘 / 그냥 복붙만 하게 해줘"라고 교정받음.
**How to apply:** 새 로직 가이드는 처음부터 평문 단위 지시문으로. 트레이드오프·체크 포인트 설명이 필요하면 지시문 코드블록 *밖*에 별도로 두고, 코드블록 안엔 Cursor 지시만 넣는다.

## 입자성 추가 보강 (2026-05-29)

paste-ready 전체 지시문보다 **더 가벼운 단위**가 요청되는 경우 있음. 사용자가 원하는 입자성은 한 가지로 고정되어 있지 않다.

**관찰 사례 (Speed Mode 운영 중, [[feedback_speed_mode_ai_first_task_split]])**:
- Task 7 진입 시 paste-ready 전체 텍스트(파일 경로 + props 시그니처 + 동작 체크리스트 + 검증 명령 + 금지 사항, 약 1000자) 제공 → 사용자: "내가 원한건 task 7에서 어떤 파일을 건드려야 하는지에 대한 정보였어. 300자 이내 답변" — 더 가벼운 파일 스코프(1~3줄)만 원했음.

**입자성 스펙트럼 (가벼움 → 무거움)**:
1. 파일 스코프 — "Task X = 어떤 파일 생성/수정?" 1~3줄
2. 인터페이스 시그니처 — props/state/관계 추가, ~10줄
3. 동작 체크리스트 — 가드/이벤트/UX 명시, ~30줄
4. paste-ready 전체 spec — 위 전부 + 검증 명령 + 금지 사항, ~50줄+

**How to apply (2026-05-29 갱신)**:
- Task 단위 가이드 시작 시 사용자가 이미 컨텍스트를 머리에 들고 있을 가능성 고려.
- 분량이 길어질 것 같으면(>500자 추정) 가장 가벼운 단위(파일 스코프)부터 제시 후 "더 필요하면 알려주세요" 형식.
- 또는 한 번 묻기: "파일 스코프만 / 인터페이스까지 / 전체 paste-ready 중 어디까지?"
- Speed Mode 진입 후에도 매 Task가 같은 분량을 요구하진 않음. 기계적 작은 변경은 파일 스코프로 충분.
