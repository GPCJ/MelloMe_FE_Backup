사용자가 작업 앞에서 정체(미루기·"못 하겠다")할 때, **대부분 능력 부족이 아니라 의욕 저하**다 (2026-06-02 본인 자각). 가끔 배경지식 부족으로 진짜 못 하는 경우도 있으나 소수.

**Why:** 2026-06-02 큰 PR 리뷰 회피 → 한 파일(`useSendMessage.ts`)씩 같이 읽으니 막힘 없이 다 읽음. 본인 결론: "읽을 줄 모르는 게 아니라 읽기 싫음이었다. 매번 이런 것 같다. 이미 가능한데 의욕이 안 나서 안 하고 있는 게 많다." 내가 설득해주면 그걸 토대로 추진력 얻어 쭉 진행.

## How to apply

1. **정체 시 능력 vs 의욕부터 구분.** "다 못 하겠다/부담된다" 호소는 거의 의욕 저하. 진짜 능력 갭(배경지식)은 콕 집힌 좌표("이 API를 모르겠다")로 나타남.
2. **의욕 저하면 "대신 해줄까?"(AI 떠먹이기) 금지.** 이는 본인 목표([[user_self_coding_goal]] AI 의존 줄이기)와 정반대. 대신 **설득·격려 + 잘게 쪼개기**(파일/유닛 하나씩)로 활성화 에너지를 낮춤.
3. 작은 단위 하나만 시작시키면 스스로 추진력 받아 쭉 진행하는 패턴. 첫 한 걸음을 같이 떼주는 데 집중.
4. 능력 갭이 진짜로 확인된 소수 경우에만 가르치기/도움으로 전환.

## 구조적 dip 변형 — 항상 "푸시"가 답은 아님 (2026-06-30 검증)

의욕 저하가 개인 게으름이 아니라 **구조적 조건**에서 올 때가 있다. 이번 트리거 3종(마감기에 자주 겹침):
1. 팀원들이 외부일정(휴가·면접)으로 이탈 → "나만 열심히 하나" 고립감.
2. 핵심목표(유입·리텐션)는 있는데 **"어떻게"가 안갯속**(아이디어 모색 단계) → 다음 구체 좌표 부재.
3. 부트캠프 같은 **외부 강제 구조 부재** → 본인이 "부트캠프 일정 있었으면 더 열심히 했으려나" 자문.

이때는 "더 밀어붙이기"보다 **작은 1건 완료 → 떳떳한 휴식 허가**가 더 맞는 대응:
1. **안 막힌 작은 1건을 같이 끝내준다.** 큰 기능들이 다 BE 블로킹이어도, FE 단독·저두뇌 작업 1건은 거의 항상 있다(이번엔 PR #31 팔로우 제거 QA·머지). "오늘 0이 아니다"를 만든다.
2. **스크럼/보고 대본을 제공한다.** 완료 보고 + **블로커를 BE로 공개 에스컬레이션**(혼자 조용히 기다리는 답답함의 절반은 "말 안 해서"). 능동 top3 제외(passive)였던 BE 대기건을 스크럼서 찌르게.
3. **죄책감 없는 휴식을 명시 허가한다.** 구조적 dip은 하루 푸시한다고 안 사라짐. 단, 순서: 작은 거 1건 끝내고 → 떳떳하게 쉬기(안 끝내고 쉬면 본인이 찜찜해함).
