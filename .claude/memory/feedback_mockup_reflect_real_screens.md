제품 화면을 묘사하는 UI(마케팅 랜딩의 폰 목업, 스크린샷, 온보딩 비주얼 등)는 **현재 앱의 실제 화면을 재현**해야 한다. 와이어프레임/시안이 지어낸 placeholder 예시 표기를 그대로 옮기지 말 것.

**근거 (2026-06-06, 랜딩 부활 작업):** Feature① 인증 목업을 PM 와이어프레임대로(🛡️ 큰 아이콘 + "면허증 등록하면 인증 회원" + 간단 칩 4개)로 구현했더니 "실제 서비스 화면과 다르다"고 교정받음 → 실제 `TherapistVerificationPage`(면허번호 입력 / 면허증 첨부 드래그 / 치료영역 9칩 3열 / 취소·인증신청 violet 버튼)로 재작성. Feature② 고민카드도 실제 `ConcernForm`(연령대→치료영역→진단명→고민지점 순, 헤더 토글, 푸터 공개범위+작성완료) 재현.

**Why:** 제품을 광고·소개하는 화면이 실제와 다르면 신규 유저 기대-실제 갭이 생기고 신뢰가 깎인다. 와이어프레임은 레이아웃 참고일 뿐 화면 내용의 정답이 아니다.

**How to apply:** 목업/스크린샷/온보딩 등 실제 화면을 묘사하는 작업은, 해당 실제 컴포넌트(예: 작성 폼·인증 폼)를 먼저 `Read`로 확인하고 필드·순서·버튼·색까지 맞춰 재현한다. 추상 기능 카드처럼 특정 화면이 아닌 비주얼은 와이어프레임대로 둬도 됨. 관련 [[project_landing_page_deprecation]].
