# 디자인 패턴 학습 진입점 (2026-05-10)

사용자가 디자인 패턴을 의도적으로 처음 사용한 사례는 2026-05-10 `lib/queryClient.ts` 작업의 **싱글턴 패턴**입니다.

## 본인 표현

> "평소엔 '패턴을 위해 패턴을 쓰는' 느낌이 있어 거리감이 있었는데, 이번엔 자연스럽게 맞아 들어가는 자리였습니다."

거리감이 있었다는 점이 중요합니다. 패턴 자체부터 가르치면 그 거리감이 다시 살아납니다.

## How to apply (다음 디자인 패턴 가이드 시)

**자리(자연스러운 적용 맥락)부터 보여주기**

- 사용자가 흡수한 길: "Provider와 store 양쪽이 같은 인스턴스를 참조해야 한다 → 그래서 모듈 export로 강제" 같은 **제약 → 해법** 순서.
- 피해야 할 길: "싱글턴 패턴이란... 인스턴스가 하나만 존재하도록 보장하는 패턴..." 같은 **정의부터 시작**. 이 톤은 사용자가 거리감을 느끼는 모드.

**왜(why) > 무엇(what)**

- 사용자가 PR 리뷰 후 "주석/PR 설명에 어떤식으로 코드 수정했는지 잘 설명해줘서 PR 리뷰가 수월하네"라고 명시한 시점이 같은 작업.
- 패턴 가이드 시에도 "이게 무엇이다" 보다 "왜 이 자리에 필요했는가"를 먼저.
