## 결정 사항

### 도구 = Google Docs
옵션 A 노션 vs B Google Docs 중 **B 채택**.
- 이유 ① 2장 PDF 분량 통제 쉬움 ② 이후 실제 회사 지원에도 재활용 ③ 본인이 직접 옮기며 작성하는 학습 효과
- 노션 한계: 페이지 분기 통제 X, PDF export 시 분량 어색해짐 가능

### 콘텐츠 방향
- **협업 스토리 1개만 유지** (BE-디자이너 의사소통 중개자) + **개발 역량 3-4개로 메인 어필**
- 본인 자기 인식 (정확함): *"개발 역량을 내세울 수 있는 사람이면서 부가적으로 협업도 잘하는 사람"*
- 협업 스토리 표현 주의: "감성적" → **"기술/디자인 언어 번역"** 같은 프레임으로 변환

### 기술 스택 표기 = 프론트엔드만
- 단독 FE라서 백엔드/인프라 부풀리면 면접에서 신뢰도 무너집니다 ("그럼 EC2 어떻게 셋업했냐" 질문에 막힘)
- 표기 스택: React 19, TypeScript, Vite, Tailwind, shadcn/ui, Zustand, React Router, React Query, MSW
- 배포 URL: `www.melonnetherapists.com`만 (api.* 제외)

### AI 활용 표현 — 경고
본인 원문: *"내가 어떻게 구현할지 구상이 완료된 부분에 대해서는 완전 자동화하고 PR을 올림"*
→ 한국 채용 시장에서 *"AI에 다 맡기는 사람"*으로 들릴 위험.

**대안 표현**:
