사용자는 **"더 이해하기 어려운 코드를 굳이 이해하고 넘어가야 기본기 튼튼한 개발자가 된다"는 강박**이 있다. 2026-06-04 `linkifyUrls` 리뷰에서, 추상화된 `.replace` 콜백 버전이 본인에게 더 잘 읽히는데도 더 어려운 "누산기 + 인덱스 커서로 문자열을 직접 훑는" loop 버전을 굳이 이해하려 했고, "이런 코드는 개발자 기본 수양으로 이해할 수 있어야 하냐"고 객관적 판단을 요청했다.

**효과적이었던 응답 프레임** (그대로 수긍도, 무조건 위로도 아닌 객관적 판정):
1. 그 패턴(누산기+커서 수동 스캔)은 파서·토크나이저·스트림·투포인터의 바탕이라 **진짜 기본기 맞음** → 강박이 가리키는 방향이 정당한 경우도 있다고 인정.
2. 단 **"첫 읽기에 술술 들어와야 기본기"는 틀린 기준** — 시니어도 상태 변하는 루프는 손으로 추적한다. 본질은 "필요할 때 정확히 추적해내는 능력"이고, 사용자는 종이 추적으로 이미 그걸 해냄.
3. **진짜 고수 = 양쪽 레벨 다 할 줄 알고 고르는 것.** 추상화 버전 선호는 약점이 아니라 도구 선택. 손으로 못 내려가는 것만 갭.
4. **경계 함정**: "어려운 코드 = 더 본질적 = 배울 가치"는 거짓일 때가 많다(우발적 복잡도일 수 있음). 더 높은 기본기는 **본질적 복잡도 vs 우발적 복잡도를 구분하는 눈**. 이번 loop 버전 복잡함은 실제 엣지케이스 정확성을 사주므로 "반쯤 본질적" → 이해할 가치 있음.

**Why:** 이 강박을 방치하면 나쁜 코드까지 "수양"이라며 억지로 내면화하거나, 첫눈에 안 들어온다고 자기 실력을 의심하는 소모가 생긴다. AI 의존 불안과도 맞닿아 있다.

**How to apply:** 사용자가 "어려운 걸 이해하고 넘어가야 한다"는 강박을 드러내면, 무조건 동조해 더 어려운 길로 끌지 말고 위 4단계로 객관 판정하라 — 특히 "본질적 vs 우발적 복잡도" 구분을 같이 세워주고, "첫 읽기 술술"이 아니라 "추적 가능"이 도달점임을 짚어라.
