# 코드 학습 시 막힘 포인트 — 의미 모르는 파라미터

사용자 직접 발화 (2026-05-13, PR #19 RQ 학습 중):
> "나는 주로 이렇게 의미를 모르겠는 파라미터들이 있는게 제일 신경쓰여"

## 무엇이 막히는가
- 매직 리터럴 (`page - 1`, `30_000`, `0`)
- 함수 인자의 의미 (`queryKey`의 두 번째 자리, `mutationFn`이 받는 args 형태)
- 옵션 키워드 (`keepPreviousData`, `staleTime`, `placeholderData`)
- 타입 단언 / 어노테이션 (`as const`)

큰 그림(라이브러리의 효용, 패러다임 비교)은 이미 알고 있는 경우가 많음. 막힘은 **미시 레벨의 "이 자리에 왜 이게 들어가는가"** 에서 발생.

## 응용 가이드 (AI 행동)
- 코드 설명 시 **의미 모를 만한 파라미터/리터럴/상수를 먼저 색출**하고 그 의미부터 짚기
- "이건 너무 기본이라 알 거야" 라고 건너뛰지 말기 — 사용자가 명시적으로 짚어달라고 한 영역
- 라이브러리 패러다임 설명 같은 큰 그림은 한 줄로 마무리, 미시 의미에 시간 더 쓰기
- 새 코드 학습 진입 시 "혹시 이 라인의 ~ 부분 의미가 헷갈리면 짚어주세요" 라는 신호 미리 주기
