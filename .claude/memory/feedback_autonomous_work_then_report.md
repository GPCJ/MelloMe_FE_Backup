사용자가 "네가 작업하고 보고해줘" 형태로 위임할 때: 코드 작성 → 커밋 → PR 생성 → 완료 보고 순서로 자율 진행.

**Why:** 사용자가 GitHub diff로 코드 리뷰하고 merge 여부를 직접 결정하는 워크플로우를 선호함. 2026-05-09 세션에서 확인.

**How to apply:**
- 작업 시작 전 feature 브랜치 분리 (develop에 직접 커밋 후 사후 이동은 불필요한 복잡성)
- PR base는 develop, 설명은 변경 파일 요약 + QA 체크리스트 포함
- 완료 보고 시: 변경된 파일 목록 + 각 파일에서 무엇이 바뀌었는지 한 줄 요약
- Jira 티켓 상태 변경은 사용자 요청 시 진행
