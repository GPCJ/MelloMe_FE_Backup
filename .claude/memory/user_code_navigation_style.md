처음 보거나 익숙하지 않은 키워드(함수명, 메서드명, 변수명)를 만나면 그것의 선언부로 점프해서 정의를 확인하는 학습 스타일입니다. 코드 작성 가이드를 줄 때도 이 흐름과 맞추는 것이 효율적입니다.

**구체 적용:**

새 기능 작성 시 inside-out(가장 안쪽 hook부터 → 바깥 호출부)보다 outside-in(호출부 본체 작성 → 배달 경로 → 가장 안쪽 hook 옵션)을 선호합니다. 본인이 진짜 작성하고 싶은 코드(실체 함수 본체)부터 시작해야 머릿속 그림이 또렷해진다고 표현했습니다.

**가이드 작성 시:**

- 처음 보는 함수/API가 등장하면 사용자가 점프해서 시그니처를 확인하고 싶어할 가능성이 높음. 가이드 안에 "이 키워드는 처음 볼 수 있음" 같은 힌트를 짧게 붙이는 것이 도움됩니다.
- 단계 끊을 때 outside-in 순서로 끊되, 중간 단계에서 tsc 에러가 발생할 수 있음을 미리 알려주면 사용자가 검증 타이밍을 잡기 쉽습니다.
