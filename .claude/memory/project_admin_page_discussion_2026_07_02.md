2026-07-02 데일리스크럼에서 나온 논의. **아직 구현·구상 단계 아님, "이런 얘기가 나왔다" 수준의 박제.**

## 발단
- PM: BE 도움 없이 **AI 자동답변(고민카드 AI 답변, [[project_concern_card_feature]])을 승인**할 수 있는 UI 같은 게 없을까?
- BE 답변: 그럴 거면 **차라리 어드민 페이지를 만드는 게 낫다.**
- 본인(FE) 의견(연장선): 그러면 **구인공고 CRUD([[project_job_posting_feature]], ADMIN only CREATE·상시모집 등)도 어드민 페이지에 같이 넣는 게 낫겠다.**

## 갈등 지점
- PM 우려: 어드민 페이지에 리소스를 쓰면, **유입·리텐션 수치 상승(마감 ~7/19 핵심 목표, [[project_pm_scrum_priority_2026_06_29]])**에 쓸 리소스를 낭비하는 것 아닌가. 확정 아닌 걱정 톤.

## 어드민 페이지 확정 시 FE가 생각해볼 지점 (미착수)
1. **BE 계약 정리** — 어떻게 API 계약을 정해서 만들지
2. **UI 방향** — 어떤 UI로 만들어 나갈지
3. **구인공고 CRUD UI 통합** — 거기에 어떻게 녹일지

**Why:** 어드민 페이지는 리텐션 목표와 리소스 경쟁 관계라 착수 자체가 미결정. FE는 만들기로 확정되면 위 3개를 준비하면 됨. 구인공고 CRUD의 "ADMIN only CREATE"가 어드민 페이지 없이는 붙일 곳이 없다는 점에서, 구인공고 Phase2와 이 논의가 연결됨.

**How to apply:** 어드민 페이지 착수가 확정되기 전엔 FE 리소스 투입 금지(PM 결정 대기, passive 항목). 확정 신호 오면 위 3개(계약·UI·구인공고 통합)부터 논의 시작. AI 자동답변 승인 = 고민카드 AI 답변 모더레이션 흐름.
