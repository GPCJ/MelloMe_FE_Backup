# 고민 카드(Concern Card) 기능 설계 스펙

- 작성일: 2026-05-27
- 단계: Post-MVP (프로토타입)
- 상태: 설계 확정, 백엔드 계약 일부 대기

## 1. 배경과 목표

발달장애 아동 치료사가 임상 고민을 구조화된 카드 형태로 게시하고, 동료 치료사에게
조언을 구하는 기능입니다. 유저는 게시글 작성 모달에서 "고민 카드"를 선택해 정해진 폼을
채우고, 저장된 카드는 홈피드에 일반 게시글과 함께 노출되며, 상세 페이지에서 전체 내용을
확인합니다.

빠르게 출시해 반응을 보는 **프로토타입**입니다. 반응이 약하면 폐기할 수 있으므로,
기존 게시글 파이프라인(피드/상세/댓글/리액션)을 최대한 재사용해 구현 비용을 낮춥니다.

## 2. 범위

포함:
- 작성 모달의 "일반 글 / 고민 카드" 타입 토글
- 고민 카드 입력 폼(고민/연령대/치료영역/진단명/기타)
- 진단명 자동완성 + 자유 입력 태그
- 피드/상세에서 고민 카드 표시(B안 레이아웃)

제외(현 단계 아님):
- 진단명 빈도 분석 기반 목록 자동 고도화(2단계)
- 진단명 enum화(데이터 축적 후 검토)
- 고민 카드 전용 필터/검색

## 3. 데이터 모델 (제안 계약 — 백엔드 확정 대기)

고민 카드는 `postType: 'CONCERN'`인 특수 게시글로 취급하며, 구조화된 `concern` 객체를
동반합니다. 이렇게 하면 피드/상세/댓글/리액션 파이프라인을 그대로 재사용할 수 있고,
진단명·치료영역 데이터가 구조화되어 추후 분석·필터링이 가능합니다.

```
Concern {
  worry: string             // 고민(본문) · 필수
  ageGroup: AgeGroup        // 연령대 · 필수 · 단일 선택 (기존 enum 재사용)
  therapyArea: TherapyArea  // 치료영역 · 필수 · 단일 선택 (기존 enum 재사용)
  diagnoses: string[]       // 진단명 · 필수(1개 이상) · 자유 문자열 배열
  note?: string             // 기타 · 선택
}
```

`AgeGroup`은 **이미 `types/post.ts`에 정의된 enum을 재사용**합니다(현재 미사용 휴면 타입,
백엔드 스펙 미러링용으로 추정). 사용자가 고른 6단계와 1:1 매칭됩니다:

| enum 값 | 라벨 |
| --- | --- |
| `AGE_0_2` | 영아기 |
| `AGE_3_5` | 유아기 |
| `AGE_6_12` | 아동기 |
| `AGE_13_18` | 청소년기 |
| `AGE_19_64` | 성년기 |
| `AGE_65_PLUS` | 노령기 |

(`UNSPECIFIED`는 고민 카드 작성 칩에서는 노출하지 않습니다.) 라벨 매핑 상수는 신설합니다.

설계 결정:
- `postType`에 `CONCERN` 추가. 기존 값은 `COMMUNITY | RESOURCE`.
- `ageGroup`은 기존 `AgeGroup` enum 재사용. `therapyArea`는 기존 `TherapyArea` enum 재사용(피드 필터칩과 동일 라벨).
- 진단명은 **자유 문자열 배열**로 저장. 백엔드는 enum/화이트리스트 검증을 하지 않습니다.
  목록은 프론트 전용 시드 상수로만 두고, 추후 빈도 분석 후 enum화를 검토합니다.
- 읽기(피드/상세)는 Post 형태(`postType=CONCERN` + `concern`)로 응답합니다.

### 진단명 입력·정제 전략 (확정)
- PM이 제공한 자주 쓰이는 진단명 목록을 시드로 두고, 프론트에서 자동완성으로 유도합니다.
- 목록 내 진단명 = 표기 통일 → 정제 불필요. 목록 외(자유 입력) = 별도 수집 후 정제 대상.
- 백엔드 비용은 두 경우 모두 동일(자유 문자열 수신)하며, 목록 유도로 데이터 품질만 향상됩니다.
- 동반진단(예: 자폐스펙트럼 + ADHD)을 고려해 복수 입력을 허용합니다.

### 백엔드 확정 대기 질문
1. 작성 엔드포인트 형태: 별도 `POST /concerns` 인지, 기존 게시글 작성에 `postType` + `concern`을
   실어 보내는지.
2. 피드 응답(`PostSummary`)에도 `concern` 객체가 동봉되는지(피드 미리보기 렌더에 필요).
3. 진단명 배열의 제약: 태그당 최대 길이, 최대 개수, 공백 trim/중복 제거 정책.

## 4. 작성 모달

- 상단에 "일반 글 / 고민 카드" 토글을 둡니다. 고민 카드 선택 시, 일반 본문 textarea 자리를
  고민 카드 폼이 대체합니다.
- 입력 순서: **고민 → 연령대 → 치료영역 → 진단명 → 기타**
- 연령대: 단일 선택 칩(영아기/유아기/아동기/청소년기/성년기/노령기)
- 치료영역: 단일 선택 칩. 본인 치료영역을 선택하며, 라벨은 피드 필터칩과 동일합니다
  (감각통합/언어치료/작업치료/인지치료/물리치료/미술치료/음악치료/놀이치료/행동치료).
- 진단명: PM 시드 목록 기반 **자동완성(커스텀 필터 드롭다운) + 자유 입력**.
  입력 후 Enter로 태그 추가, ✕로 제거, 복수 허용.
- 기타: 유일한 선택(비필수) 항목. 부연 설명용.
- 필수 검증: 고민(비어 있지 않음), 연령대 선택, 치료영역 선택, 진단명 1개 이상. 기타는 선택.
- 칩·태그 선택 색상은 **무채색**(`bg-gray-900 text-white`)으로 기존 FilterChips 컨벤션을 따릅니다.
- 기존 공개범위(visibility) 컨트롤은 유지합니다.

### 진단명 자동완성 구현 수준
- 시드 목록은 정적 클라이언트 상수(서버 호출/비동기 없음). 입력값으로 즉시 필터링합니다.
- 후보 드롭다운 클릭 또는 자유 입력 Enter로 태그를 추가합니다.
- 프로토타입 단계에서 키보드 화살표 탐색·ARIA 콤보박스는 생략 가능합니다(마우스/탭 클릭 + Enter로 충분).

## 5. 표시 (피드/상세 — B안, 완전 통일)

카드 내부 순서:
1. 카드 헤더: 아이콘 + "고민카드" 라벨
2. 메타: 연령대 / 치료영역 / 진단명(인라인 무채색 태그)
3. 구분선
4. "고민지점" 라벨 + 고민 본문
5. 기타(부연 설명)는 입력된 경우에만 맨 아래 작게 표시

- 피드: 고민 본문에 `line-clamp-3` 적용 + "더보기"(기존 PostCard 패턴 재사용).
- 상세: clamp 해제, 전체 노출. 그 외 피드와 완전 동일한 카드.
- 작성자 헤더(아바타/닉네임/인증뱃지/시간)와 푸터(리액션/댓글/공유/북마크)는 기존 게시글과 동일합니다.

## 6. 프론트 구현 경계

백엔드 독립(지금 구현 가능):
- FE 내부 타입 `Concern` 정의 후 UI·표시 컴포넌트를 이 타입에 맞춰 구현합니다.
- 신규 컴포넌트
  - `ConcernCard`: 피드/상세 공용 표시 컴포넌트(clamp 여부만 prop으로 분기)
  - `ConcernForm`: 작성 폼(고민/연령대/치료영역/진단명/기타)
  - `DiagnosisTagInput`: 자동완성 + 자유 입력 태그
- 상수: 시드 진단명 목록, `AgeGroup` 라벨 매핑을 `constants`에 둡니다.

백엔드 계약 의존(어댑터로 격리):
- API 매핑을 `api/concerns.ts` 한 곳에 격리합니다. 백엔드 계약이 확정되면 이 매핑만
  수정하고 UI는 건드리지 않습니다.
- 기존 분기: `PostCard`/`PostDetailPage`에서 `postType === 'CONCERN'`이면 `ConcernCard`를
  렌더합니다.

## 7. 테스트

- 환경은 MSW=false / staging 기반입니다. 백엔드 엔드포인트 완성 후 staging에서 직접 검증합니다.
- 백엔드 독립 부분(폼 검증, 태그 입력, 카드 렌더)은 로컬에서 목 데이터로 확인합니다.

## 8. 미결 사항

- 백엔드 계약 3개 질문(3절) — 백엔드 전달 후 확정.
- 치료영역 단일 선택(PM 합의 완료), 진단명 복수 허용(PM 합의 완료).
